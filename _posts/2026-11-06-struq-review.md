StruQ: 구조화된 쿼리를 이용한 프롬프트 인젝션 방어

<strong>게재:</strong> USENIX Security Symposium 2025<br /><strong>저자:</strong> Sizhe Chen, Julien Piet, Chawin Sitawarin, David Wagner

> <strong>한 문장 요약:</strong> AI가 따라야 할 명령과 읽어야 할 자료를 구분하고, 자료 속 명령을 무시하도록 학습시켜 프롬프트 인젝션에 대한 저항력을 높이는 연구이다.

## 1. 배경과 문제의식

### 어떤 문제를 해결하려는가?

LLM 기반 애플리케이션은 개발자가 정한 작업 지시와 외부 입력 데이터를 함께 처리한다. 이때 모델이 데이터에 포함된 지시를 실행할 명령으로 받아들이면, 애플리케이션이 의도한 작업에서 벗어날 수 있다.

이처럼 <strong>입력 자료에 명령을 넣어 모델의 행동을 바꾸는 공격</strong>을 프롬프트 인젝션(Prompt Injection)이라고 한다. 문서나 로그를 읽는 서비스에서는 분석 대상 자체가 공격의 통로가 될 수 있다는 점에서 중요하다.

공격 문장에 위험한 내용이 없어도 원래 작업을 바꾸면 문제가 된다. 따라서 단순히 유해한 단어를 찾는 방식으로는 판단하기 어렵다.

### 기존 방식은 무엇이 부족했는가?

기존에는 입력에 경고 문구를 넣거나, 구분자로 데이터를 감싸는 방법을 사용했다. 하지만 모델이 그 경계를 일관되게 따르도록 학습된 것은 아니므로, 구분자를 흉내 내거나 새로운 대화처럼 꾸민 공격에 흔들릴 수 있다.

특정 작업만 수행하도록 학습하는 Jatmo나, 구분자와 공격 예제를 활용하는 BIPIA 같은 연구도 있었다. StruQ는 <strong>입력 경계를 보호하는 프런트엔드와 그 경계를 따르는 모델 학습을 함께 설계</strong>하는 데 초점을 둔다.

이 논문은 공격자가 <strong>데이터 영역은 바꿀 수 있지만 애플리케이션의 명령 영역은 바꿀 수 없다</strong>고 가정한다. 외부 자료가 실수로 명령 영역에 들어가면 이 가정이 무너지므로, 애플리케이션도 입력을 올바르게 구분해야 한다.

```txt
신뢰 경계(Trust Boundary)
- 서로 다른 신뢰 수준이나 권한을 구분하는 경계
- StruQ에서는 신뢰하는 작업 지시와 신뢰하지 않는 외부 데이터를 구분한다.

위협 모델(Threat Model)
- 공격자의 목표, 지식, 접근 권한과 시스템의 보호 대상을 정한 가정
- 이 논문의 공격자는 데이터 영역을 바꿀 수 있지만 명령 영역은 바꾸지 못한다.

프롬프트 인젝션(Prompt Injection)
- 입력 데이터에 삽입된 지시가 애플리케이션의 원래 작업을 바꾸도록 유도하는 공격

탈옥(Jailbreak)
- 모델 제공자가 설정한 안전 제한을 우회하여 제한된 응답을 얻으려는 공격
```

## 2. 핵심 아이디어와 방법

### 2-1. 전체 구조

핵심 아이디어는 <strong>“따라야 할 명령과 읽어야 할 자료를 구분하고, 모델도 그 구분에 맞게 행동하도록 학습하자”</strong>는 것이다.

StruQ는 보안 프런트엔드(Secure Front-End)와 구조화된 지시 튜닝(Structured Instruction Tuning)을 거친 LLM으로 구성된다.

| 구성 요소 | 역할 |
| --- | --- |
| 보안 프런트엔드<br />(Secure Front-End) | 특수 토큰으로 명령과 데이터를 구분하고, 데이터에서 경계를 위조하는 문자열을 제거한다. |
| 구조화된 지시 튜닝<br />(Structured Instruction Tuning) | 모델이 명령 영역의 지시를 따르고, 데이터 속 지시는 무시하도록 학습한다. |

명령과 데이터는 서로 구분하여 입력받지만, 모델에 전달할 때는 <strong>특수 토큰으로 나뉜 하나의 입력 시퀀스</strong>로 구성한다.

```txt
구조화된 쿼리(Structured Query)
- 명령과 데이터를 구분된 영역으로 표현하는 입력 방식

입력 시퀀스(Input Sequence)
- 모델에 순서대로 전달되는 토큰의 나열

구분자(Delimiter)
- 입력 안에서 영역의 시작과 끝을 표시하는 표식
```

### 2-2. 보안 프런트엔드(Secure Front-End)

프런트엔드는 모델 앞에서 입력을 정리하는 구성 요소이다. 명령·데이터·응답 영역을 특수 토큰으로 표시하고, 데이터에 들어 있는 경계 위조 문자열을 제거한다.

| 토큰 | 역할 |
| --- | --- |
| <code>[MARK]</code> | 구분 시작 |
| <code>[INST]</code> | 명령 영역 |
| <code>[INPT]</code> | 데이터 영역 |
| <code>[RESP]</code> | 응답 영역 |
| <code>[COLN]</code> | 구분 형식에서 콜론 역할 |

공격자가 데이터 안에 같은 표식을 넣으면 새로운 명령 영역처럼 보이게 만들 수 있다. 이를 막기 위해 프런트엔드는 예약 구분자 문자열과 <code>##</code>를 제거한다. 삭제 후 새로운 표식이 만들어질 수도 있으므로, 더 이상 바뀌지 않을 때까지 반복한다.

<strong>필터가 담당하는 것은 경계 위조 문자열의 제거이다.</strong> 일반 자연어로 작성된 공격 지시를 무시하는 역할은 모델의 학습이 담당한다.

### 2-3. 구조화된 지시 튜닝(Structured Instruction Tuning)

지시 튜닝(Instruction Tuning)은 모델에 명령과 바람직한 답의 예시를 보여주어 작업 수행 능력을 학습시키는 과정이다. StruQ는 지시 튜닝 이전의 기본 모델(Base Model)에서 출발해, <strong>명령을 수행하는 능력과 명령의 위치를 구분하는 능력</strong>을 함께 학습시킨다.

정상 예제와 공격이 포함된 예제를 섞되, <strong>공격이 들어가도 정답은 원래 작업의 답으로 유지한다.</strong>

이렇게 학습하면 모델은 데이터에서 필요한 정보를 활용하면서도, 데이터 속 지시에 따라 작업을 바꾸지 않도록 훈련된다.

| 학습 예제 | 기본 배분 | 목적 |
| --- | --- | --- |
| 정상 예제(Clean) | 50% | 정상 작업 능력 유지 |
| 단순 공격 예제(Naive) | 25% | 자료에 추가된 다른 명령을 무시하도록 학습 |
| 완료 위장 공격 예제(Completion-Other) | 25% | 가짜 답변과 새 질문에 속지 않도록 학습 |

데이터 영역이 비어 있는 예제는 공격을 추가하지 않으므로, 실제 공격 포함 비율이 항상 정확히 50%인 것은 아니다.

Completion 예제는 답변이 이미 끝난 것처럼 꾸민 뒤 다른 명령을 넣는다. 학습용 가짜 응답은 원래 정답과 다르게 구성한다. 정답이 이미 입력에 있으면 모델이 명령을 구분하는 대신 답을 복사하는 방식으로 학습할 수 있기 때문이다.

### 2-4. 이 방법에서 중요한 점

<strong>입력 형식만 바꾸는 것과 모델을 학습시키는 것이 함께 필요하다.</strong> 일반 챗봇에 위의 표식을 붙이는 것만으로 StruQ가 구현되지는 않는다. 해당 표식이 특수 토큰으로 처리되고, 모델도 그 구조를 따르도록 학습되어 있어야 한다.

```txt
토큰(Token)
- 모델이 텍스트를 처리하는 단위. 단어, 단어의 일부, 기호 등으로 나뉠 수 있다.

특수 토큰(Special Token)
- 일반 텍스트와 구별되는 역할을 부여한 토큰
- StruQ에서는 명령·데이터·응답 영역을 표시하는 데 사용한다.

예약 구분자(Reserved Delimiter)
- 시스템의 입력 구조를 표시하기 위해 따로 정해둔 구분자
- 외부 데이터가 이를 위조하지 못하도록 프런트엔드가 처리한다.

기본 모델(Base Model)
- 대규모 텍스트로 사전 학습했지만 지시 튜닝은 하지 않은 모델

파인튜닝(Fine-Tuning)
- 사전 학습된 모델을 특정 목적의 데이터로 추가 학습시키는 과정

지시 튜닝(Instruction Tuning)
- 명령과 바람직한 응답을 이용해 지시 수행 능력을 학습시키는 파인튜닝 방식

구조화된 지시 튜닝(Structured Instruction Tuning)
- 명령과 데이터가 구분된 입력으로 학습하여 명령 영역의 지시를 따르게 하는 방식

임베딩(Embedding)
- 토큰을 모델이 계산할 수 있는 숫자 벡터로 표현한 것

데이터 증강(Data Augmentation)
- 기존 데이터를 변형하여 학습에 사용할 데이터를 늘리는 방법
- StruQ에서는 데이터 영역에 공격 지시를 추가하고 원래 정답을 유지한다.
```

## 3. 실험과 주요 결과

### 3-1. 무엇을 평가했는가?

저자들은 <strong>Llama-7B와 Mistral-7B</strong> 기본 모델에 StruQ를 적용하고, 방어를 적용하지 않은 비교 모델과 평가했다. 정제된 Alpaca 지시 데이터셋으로 모델을 3 에포크(Epoch) 학습했다.

평가에서는 <strong>공격을 막는 능력과 정상 작업 수행 능력</strong>을 함께 본다. 모든 요청을 거부하면 공격 성공률은 낮아질 수 있지만, 실제 서비스로 사용하기 어렵기 때문이다.

| 평가 항목 | 지표와 자료 |
| --- | --- |
| 보안 | 공격 성공률(ASR). 주로 데이터 입력이 있는 AlpacaFarm 예제 208개 사용 |
| 정상 작업 성능 | AlpacaEval 1.0 승률. 예제 805개의 답변을 GPT-4가 기준 모델의 답과 비교 |

공격 평가는 주로 원래 작업 대신 지정한 문자열을 출력하게 하는 방식이다. 따라서 이 결과만으로 모든 종류의 정보 유출이나 판단 왜곡을 평가했다고 보기는 어렵다.

```txt
공격 성공률(Attack Success Rate, ASR)
- 평가한 공격 시도 중 공격자의 목표가 달성된 비율. 낮을수록 좋다.

유용성(Utility)
- 모델이 원래 의도된 작업을 얼마나 잘 수행하는지를 나타내는 성질

Alpaca
- 지시 튜닝에 사용하는 데이터셋. 이 논문에서는 정제된 버전을 학습에 사용한다.

AlpacaFarm
- 이 논문에서 보안 및 정상 작업 평가에 사용하는 지시 데이터의 출처

AlpacaEval
- 모델의 응답을 기준 모델의 응답과 비교하여 평가하는 도구
- 이 논문은 AlpacaEval 1.0을 사용한다.

승률(Win Rate)
- 비교 대상보다 응답이 더 좋다고 평가된 비율
- 정답률이나 공격 방어율과는 다른 지표이다.

에포크(Epoch)
- 학습 데이터 전체를 한 번 처리하는 단위

매개변수(Parameter)
- 학습 과정에서 조정되는 모델 내부의 수치
- 7B는 약 70억 개의 매개변수를 가진 모델을 뜻한다.
```

### 3-2. 공격 방어 결과

아래는 대표 공격의 성공률이다.

| 공격 | Llama 방어 전 → StruQ | Mistral 방어 전 → StruQ |
| --- | --- | --- |
| Naive | 6% → 0% | 5% → 0% |
| Completion-Other | 29% → 0% | 71% → 0% |
| Completion-Real | 96% → 0% | 96% → 0% |
| HackAPrompt | 52% → 0% | 38% → 0% |
| TAP | 97% → 9% | 100% → 36% |
| GCG | 97% → 58% | 99% → 56% |

```txt
Naive
- 자료 뒤에 다른 명령을 덧붙이는 공격

Completion
- 원래 답변이 끝난 것처럼 꾸민 뒤 새 명령을 제시하는 공격
- Real: 원래 입력 형식의 구분자 사용
- Other: 다른 구분자 사용

HackAPrompt
- 사람이 만든 공격 사례를 모은 데이터셋

TAP(Tree-of-Attacks with Pruning)
- LLM으로 공격 후보를 만들고 개선하는 방식

GCG(Greedy Coordinate Gradient)
- 모델 내부의 기울기를 활용해 공격 문자열을 최적화하는 방식
```

여러 수작업 공격에서는 성공률이 크게 낮아졌다. 특히 Completion-Real은 두 모델 모두 <strong>96%에서 0%</strong>로 감소했다. 반면 GCG는 적용 후에도 <strong>58%, 56%</strong>로 남아 강한 최적화 공격에 대한 한계가 드러났다.

GCG는 모델 내부 정보에 접근하는 화이트박스(White-Box) 공격이므로 TAP과 공격 조건이 다르다. 또한 0%는 해당 실험에서 성공 사례가 관찰되지 않았다는 뜻이며, 모든 공격에 대한 안전을 보장하지는 않는다.

```txt
화이트박스 공격(White-Box Attack)
- 모델 내부 정보에 접근하여 수행하는 공격
- GCG는 모델의 기울기 정보를 활용한다.

기울기(Gradient)
- 입력이나 매개변수의 변화에 따라 목표 함수의 값이 어떻게 변하는지 나타내는 정보
- GCG는 이를 활용하여 공격 목표에 유리한 토큰 후보를 탐색한다.

최적화(Optimization)
- 정해진 목표를 더 잘 달성하도록 입력이나 매개변수를 조정하는 과정

적응형 공격(Adaptive Attack)
- 방어 방식에 대한 정보를 이용하여 그 방어를 우회하도록 설계한 공격
```

### 3-3. 정상 작업 성능과 결과 해석

| 모델 | 방어 전 승률 | StruQ 승률 | 변화 |
| --- | --- | --- | --- |
| Llama | 67.2% | 67.6% | +0.4%p |
| Mistral | 80.0% | 78.7% | -1.3%p |

정상 작업 성능은 대체로 유지되었다. 다만 Llama의 작은 상승만으로 일반적인 성능 향상을 주장하기는 어렵고, Mistral에서는 소폭 하락했다.

저자들은 구성 요소를 바꾸거나 제거하는 <strong>절제 실험(Ablation Study)</strong>도 수행했다. 학습 예제의 조합과 특수 구분자의 구성을 비교하여 각 요소가 보안과 유용성에 기여하는지 확인했다. 가짜 구분자가 있으면 무조건 거부하도록 학습하는 방식은 정상 입력까지 거부해 유용성을 낮출 수 있었다.

따라서 이 연구의 성과는 <strong>입력 구조와 학습을 결합하여 여러 공격에 대한 저항력을 높이고, 정상 작업 능력을 대체로 유지했다</strong>는 것으로 정리할 수 있다.

```txt
절제 실험(Ablation Study)
- 시스템의 일부 요소를 제거하거나 바꾸어 그 요소가 결과에 기여하는 정도를 확인하는 실험

일반화(Generalization)
- 학습에 사용하지 않은 데이터나 공격에서도 학습한 능력이 유지되는 성질

퍼센트포인트(Percentage Point, %p)
- 두 백분율의 수치 차이를 나타내는 단위
```

## 4. 강점과 한계

### 강점

<strong>첫째, 명령과 데이터의 구분을 시스템 설계에 반영했다.</strong> 경고 문구에만 의존하지 않고, 프런트엔드와 모델 학습이 각각 어떤 역할을 맡아야 하는지 제시했다.

<strong>둘째, 보안과 유용성을 함께 평가했다.</strong> 공격을 차단하면서도 원래 작업을 수행할 수 있는지 확인하여, 실제 활용 가능성을 판단할 근거를 제공했다.

<strong>셋째, 학습에 사용한 유형 외의 공격도 평가했다.</strong> Naive와 Completion-Other 중심으로 학습한 뒤 다양한 공격을 시험하여, 배운 구분 능력이 어디까지 이어지는지와 어디에서 실패하는지를 보여주었다.

### 한계와 추가로 검토할 점

- <strong>강한 공격에는 취약점이 남는다.</strong> TAP과 GCG에서 성공 사례가 있어 완전한 방어로 볼 수 없다.
- <strong>적용 범위에 조건이 있다.</strong> 명령과 데이터를 구분해 모델을 호출하는 애플리케이션이 대상이다. 자유로운 다중 턴 대화 전체를 검증한 결과는 아니다.
- <strong>다른 환경에서의 검증이 필요하다.</strong> 두 7B 모델 중심의 결과이므로 한국어, 긴 문서, 다른 규모의 모델에서도 효과가 유지되는지 확인해야 한다.
- <strong>추가 학습이 필요하다.</strong> 프롬프트만 수정하는 방어보다 모델과 학습 환경을 준비하는 부담이 크다.

리뷰 관점에서 더 확인하고 싶은 부분은 <strong>필터가 정상 자료에 미치는 영향</strong>이다. <code>##</code>나 예약 표식을 제거하면 마크다운, 코드, 로그의 내용도 바뀔 수 있다. 공격 성공률뿐 아니라 필요한 정보가 보존되는지도 자료 유형별로 측정할 필요가 있다.

또한 지정 문자열을 출력시키는 공격과, 분석 결과를 미묘하게 왜곡하는 공격은 다를 수 있다. 실제 서비스에 적용할 때는 <strong>그 서비스에서 무엇을 공격 성공으로 볼지</strong>도 함께 정의해야 한다.

## 5. 핵심 관점과 배울 점

이 논문에서 주목할 점은 <strong>지시의 내용뿐 아니라 출처와 권한을 구분한다</strong>는 것이다. 데이터에 포함된 지시가 원래 작업을 변경하는지를 기준으로 공격을 판단한다.

또한 모델은 데이터를 통째로 무시하는 것이 아니라, <strong>필요한 정보는 사용하면서 자료 속 명령은 따르지 않도록</strong> 학습한다. 보안과 정상 작업 능력을 함께 유지하려는 설계라는 점에서 의미가 있다.

StruQ는 모든 프롬프트 인젝션을 해결하지는 못했다. 그러나 명령과 데이터가 섞이는 문제를 입력 인터페이스와 학습 양쪽에서 다루었다는 점이 주요 기여이다. LLM을 분석 도구에 연결할 때도 어떤 입력에 명령 권한을 줄지 먼저 생각하게 한다.

## 6. 앞으로 할 것

### 이어서 읽을 논문과 코드

- [<strong>SecAlign: Defending Against Prompt Injection with Preference Optimization</strong>](https://sizhe-chen.github.io/SecAlign-Website/) — ACM CCS 2025. 정상 지시를 따른 응답과 공격 지시를 따른 응답을 비교하는 선호 최적화 방식이 StruQ의 학습과 어떻게 다른지 살펴본다.
- [<strong>StruQ 공식 코드</strong>](https://github.com/Sizhe-Chen/StruQ)에서 반복 필터와 공격 학습 예제를 생성하는 부분을 확인한다. 특히 공격을 추가한 뒤에도 원래 정답을 유지하는지 따라가 본다.

### 추가로 공부할 개념

- <strong>선호 최적화(Preference Optimization):</strong> 더 바람직한 응답과 덜 바람직한 응답을 비교하여, 모델이 바람직한 응답을 더 선호하도록 학습하는 방법이다.
- <strong>추론(Inference):</strong> 학습을 마친 모델이 입력을 받아 출력을 생성하는 과정이다.
- <strong>입력 시점 방어(Test-Time Defense):</strong> 모델을 다시 학습시키지 않고, 실제 사용 시 입력 처리나 지시 구성으로 공격을 줄이는 방법이다.

### 이후 확인할 내용

공식 코드에서 <strong>특수 토큰 처리, 반복 필터, 학습 데이터 구성</strong>이 연결되는 과정을 확인한다. 이어서 학습 데이터의 조합과 프런트엔드 구성을 바꾼 절제 실험을 비교한다.

확장 가능성은 한국어 보안 분석 자료에서의 공격 저항력과 정상 작업 성능을 함께 평가하는 방향으로 검토한다. 특히 필터가 분석에 필요한 정보를 보존하는지 확인할 필요가 있다.

### + 위 논문을 읽으면서 느낀 점

전에는 LLM을 개인적으로 사용하면서 활용 방법을 공부하고 개선점을 찾아보는 데 집중했다. 이번에는 보안 관련 논문을 읽으면서 LLM을 더 깊이 이해하게 된 것 같고, 생소했던 개념들을 많이 알아갈 수 있어서 좋았다.

개인적으로 탈옥과 프롬프트 인젝션의 차이를 명확하게 구분하지 못했는데, 논문을 읽고 정리하면서 두 개념의 차이를 이해할 수 있었다. 프롬프트 인젝션의 원리와 이를 방어하기 위한 접근 방식도 더 자세히 알게 되어 얻어가는 것이 많았다고 생각한다.

특히 프롬프트 인젝션을 방어하는 방식이 가장 인상 깊었다. 명령 영역과 데이터 영역을 구분하고, 학습할 때 데이터에 공격 지시가 들어가더라도 원래 명령에 맞는 답을 정답으로 유지한다는 점이 생소했다. 모델이 데이터를 읽으면서도 그 안의 지시에는 따르지 않도록 만든다는 점에서, 연구자들이 문제의 원인과 방어 방법을 깊게 고민했다는 생각이 들었다.

다만 TAP, GCG처럼 공격 입력을 반복적으로 개선하는 공격에서는 여전히 높은 공격 성공률이 남았다. 따라서 StruQ만으로 완전한 방어가 가능하다고 보기는 어렵고, 이런 공격에도 대응할 수 있는 추가적인 방어 방법이 필요하다고 생각한다.
