EIP-7702는 일반 이더리움 지갑인 EOA가 스마트 컨트랙트의 기능을 사용할 수 있게 만드는 이더리움 개선안이다.

EIP-7702를 학습하기 전에 여기에서 나오는 EOA가 무엇인지부터 간단하게 설명하고 시작해 보도록 하겠다.

#### 배경 개념 - EOA(Externally Owned Account)

메타마스크에서 생성하는 일반적인 지갑을 EOA라고 부른다.

EOA는 개인키로 관리되며 기본적으로 하는 일이 단순하다고 할 수 있다.

```py
ETH 전송
토큰 전송
스마트 컨트랙트 함수 호출
트랜잭션 서명
```

하지만 EOA 자체에는 스마트 컨트랙트 코드가 없기 때문에 다음과 같은 복잡한 기능을 직접 수행하기 어렵다.

```py
여러 작업을 한 번에 실행
다른 사람이 가스비 대신 지불
하루 사용 한도 설정
특정 서비스에만 권한 부여
보조 키나 복구 키 사용
```

#### 왜 등장했을까?

기존 EOA는 스마트 컨트랙트 코드가 없어서 여러 작업을 묶거나, 가스비를 대신 내거나, 세부적인 권한을 설정하는 기능을 직접 구현하기 어렵다.<br />이러한 EOA의 한계를 기존 지갑 주소를 유지한 채 개선하기 위해 EIP-7702가 등장했다.

#### 핵심 동작 방식

EIP-7702를 이용하면 EOA가 특정 스마트 컨트랙트 코드를 가리키도록 설정할 수 있다.

```py
기존 EOA
내 지갑 → 단순한 거래만 실행

EIP-7702 적용 후
내 지갑 → 스마트 컨트랙트 코드에 실행 위임
       → 스마트 컨트랙트 기능 사용
```

스마트 컨트랙트 코드 자체가 내 지갑 안으로 복사되는 것은 아니지만, 계정에는 정보가 새롭게 설정된다. (이 계정이 호출되면 A 스마트 컨트랙트의 코드를 실행하라 등등)

그리고 이것을 우리는 간단하게 <b>코드 위임(code delegation)</b>이라고 부른다.<br />위임받은 코드는 자신의 컨트랙트 주소가 아닌 <b>사용자의 EOA 환경에서 실행된다.</b>

따라서 기존 지갑이 보유한 ETH, 토큰 및 저장 공간을 활용해 스마트 계정처럼 동작할 수 있다.

#### 핵심 기능

```py
여러 작업 동시 가능
가스비(돈)를 대신 내줌
제한된 권한 설정
기존의 지갑 주소를 유지할 수 있음
```

#### 솔리디티와의 관계

스마트 기능을 제공할 위임 컨트랙트를 솔리디티로 작성할 수 있다.

```py
Solidity
  ↓ 작성

위임용 스마트 컨트랙트
  ↓ EIP-7702로 연결

기존 EOA가 스마트 계정처럼 동작
```

EIP-7702는 프로그래밍 언어가 아니라, EOA가 스마트 컨트랙트 코드에 동작을 위임할 수 있도록 이더리움 프로토콜에 추가된 규칙이기 때문에 이렇게 솔리디티를 활용할 수 있다.

#### 주의할 점

EIP-7702에서 가장 중요한 점은 어떤 코드에 권한을 위임하는가이다.

악성 코드나 취약한 코드에 위임하면 다음과 같은 피해가 발생할 수 있다.

```py
지갑의 ETH 또는 토큰 탈취
서명 재사용 공격
공격자가 원하는 컨트랙트 호출
잘못된 권한이나 초기화 설정
위임 컨트랙트 변경 과정의 데이터 충돌
```

따라서 사용자는 지갑에 표시되는 서명을 무심코 승인하면 안 되고, 지갑 서비스는 신뢰할 수 있고 충분히 검증된 위임 코드를 사용해야 한다.

#### 실제 이더리움 메인넷 사례 - MetaMask Smart Account

MetaMask Smart Account는 EIP-7702를 이용해 기존 EOA가 MetaMask의 위임 컨트랙트 코드를 사용할 수 있도록 한다.

- 위임 컨트랙트 주소 : <code>0x63c0c19a282a1b52b07dD5a65b58948A07DAE32B</code>
- [MetaMask EIP-7702 Delegator 확인하기](https://etherscan.io/address/0x63c0c19a282a1b52b07dd5a65b58948a07dae32b)
- [실제 Authorization 트랜잭션 확인하기](https://etherscan.io/tx/0x07180e1493245ae2781d0faf9f02a2bbb768ec9efedc50383cfe6eac0b63f640)

실제 트랜잭션에서는 Authority, Delegated Address, Nonce가 포함된 Authorization List를 확인할 수 있다.<br />이를 통해 기존 EOA가 자신의 주소를 변경하지 않고 스마트 컨트랙트 코드에 실행을 위임하는 방식을 확인할 수 있다.

#### 한 줄 정리

> EIP-7702는 기존 EOA가 자신의 주소를 유지하면서 스마트 컨트랙트 코드에 동작을 위임할 수 있게 만든 규칙이다.
