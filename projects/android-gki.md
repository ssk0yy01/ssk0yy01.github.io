## 프로젝트 목표

어떤 사용자 공간 주체가 어떤 커널 인터페이스에 접근할 수 있는지, 그 근거를 연결하는 분석기를 만드는 팀 프로젝트입니다. 현재 1차 작업에서는 커널 소스의 인터페이스 후보와 설정 조건, 핸들러·등록 경로의 정적 근거를 모읍니다.

## 담당 역할

소스에서 인터페이스 후보를 찾고, **발견한 후보·설정 때문에 제외된 후보·아직 해석하지 못한 항목**을 구분해 재확인할 수 있도록 정리합니다. 소스 조사, 설정·Kbuild 해석, 계열별 사례 검증이 담당 범위입니다.

예를 들어 `file_operations.unlocked_ioctl = foo_ioctl`에서 `foo_ioctl`은 ioctl 요청을 처리하는 콜백 후보입니다. 후보를 발견한 뒤 설정 조건과 등록 경로를 살피며, 소스에 있다는 사실만으로 앱에서 호출할 수 있다고 판단하지 않습니다.

## 진행 기록

아래 내용은 **2026년 10월 19일 Notion 기록 기준**입니다. 기존 팀 분석기를 검토하고 실험·검수한 결과이며, 분석기 기능을 새로 구현한 성과와는 구분합니다.

### 입력 기준과 재현 환경 정리

- 전달받은 원본 29개 파일의 해시를 기록하고 구현·테스트·문서를 검토했습니다.
- 기존 Pixel 7 소스를 유지하면서 팀 README에 명시된 Android 14 / Linux 6.1 common 커널 원본을 별도로 확보했습니다.
- 커밋, 로컬 수정 상태, 도구 버전, 실행 명령과 로그를 기록했습니다. 팀의 로컬 수정 13개는 이번 입력에 반영되지 않았습니다.

### 설정 조건 실험

- **파일 전체 제외:** 설정을 바꿔도 후보 21개를 보존하면서 대상 파일의 `EXCLUDED` / `SELECTED` 상태가 바뀌는지 확인했습니다.
- **파일 내부 분기:** 후보 21개 중 두 분기 후보만 예상대로 달라지고, 나머지 19개는 동일한지 확인했습니다.
- **built-in / module:** 작은 예제에서 `IS_ENABLED`와 `IS_REACHABLE`의 문맥 차이가 예상과 일치하는지 확인했습니다.

### 기존 동작 검증

기존 테스트 42개, 작은 Clang 예제 2개, README 커밋의 실제 커널 소스 테스트 14개에 대한 통과 기록을 확보했습니다. **서로 다른 시점과 일부 다른 환경에서 실행한 결과**이며, 전체 58개를 한 번에 실행한 결과는 아닙니다.

실제 소스 테스트는 15개 C 파일에 걸친 14개 검사로, Binder·eventfd·procfs·socket·block·sysctl·Netlink·configfs 등의 선택된 사례를 다룹니다. 해당 실행에서는 실패·오류·건너뜀 없이 통과했습니다.

별도 검수에서 실행기·테스트·로그와 입력 해시를 대조했습니다. 검수 항목 수는 새로 실행한 테스트 수에 포함하지 않았습니다.

## 현재 확인 범위

대표 사례의 기존 동작 검증을 마쳤으며, 전체 소스의 조사 범위와 누락 기준선 작성은 아직 완료되지 않았습니다. 전체 추출 정확도, 최종 빌드 포함 여부, 실기기 접근 가능성 또는 취약점 영향을 확정한 단계가 아닙니다.

실제 최종 `.config`와 compilation database는 이번 검증 대상에 포함되지 않았습니다. 현재 산출물은 입력·실험·검수 기록이며, 프로젝트는 **진행중**입니다.
